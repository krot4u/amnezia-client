# Amnezia Home для Android

Кастомная сборка официальной AmneziaVPN с автоматическим выключением VPN в домашних Wi-Fi и включением вне дома. Базовый релиз: **5.1.0.6**, Android **12+**, **arm64-v8a** (в том числе Vivo X300 FE, Android 16).

## Что делает

- Несколько домашних SSID; имя сети сравнивается точно, с учётом регистра.
- Через 5 секунд после изменения сети выключает VPN дома или запускает последний вручную использованный профиль вне дома. Это также работает при подключении к чужому Wi-Fi.
- Отдельная постоянная служба продолжает следить за сетью, когда сам VPN остановлен. После перезагрузки или обновления APK пытается восстановить включённую автоматику.
- При недоступном SSID или отозванных разрешениях сохраняет текущее состояние VPN и показывает причину. Не считает неизвестную сеть домашней.
- Вне дома повторяет неудачный запуск не чаще раза в минуту. Переключатель автоматизации позволяет временно вернуть ручное управление.

Это автоматизация подключения, а не защита от утечки: до установления VPN и во время задержки трафик может идти напрямую. Не включайте Android «Блокировать подключения без VPN», если дома нужен интернет без VPN. Режим Always-on не нужен и может противодействовать автоматике.

## Первый запуск

1. Установить **Amnezia Home** рядом с официальной Amnezia. Пакет `org.amnezia.vpn.home` не заменяет `org.amnezia.vpn`; официальное приложение и его данные сохраняются.
2. Перенести нужный профиль/резервную копию через штатные экспорт и импорт Amnezia. Не удалять официальное приложение до проверки импорта. Резервная копия содержит чувствительные данные; не класть её в GitHub, репозиторий или логи.
3. Один раз вручную подключить нужный профиль в Amnezia Home и подтвердить системный запрос VPN.
4. Открыть **Настройки → Подключение → Домашний Wi-Fi**. Добавить текущую домашнюю сеть или её SSID вручную. При необходимости добавить вторую домашнюю сеть.
5. Разрешить точное местоположение и доступ к нему **всегда**, включить системную службу геолокации: Android использует эти разрешения для чтения SSID в фоне. Приложение не запрашивает координаты и не отправляет SSID в сеть. Разрешить уведомления, чтобы видеть статус и обновления.
6. На Vivo разрешить автозапуск/работу в фоне в системных настройках приложения. Названия пунктов зависят от OriginOS. После принудительной остановки приложения открыть его заново.
7. Включить автоматизацию. При отключении автоматизации текущее VPN-соединение остаётся под ручным управлением.

## Обновления

Workflow `.github/workflows/home-wifi.yml` ежедневно в 07:17 UTC:

1. Проверяет последний стабильный релиз `amnezia-vpn/amnezia-client` и хеш нашей правки.
2. Берёт чистые официальные исходники и применяет `feature.patch` с обязательным `git apply --check`.
3. Собирает Android arm64 APK, подписывает **одним постоянным ключом**, проверяет подпись.
4. Только после успешной сборки публикует релиз `home-<versionCode>` с APK и SHA256SUMS в пользовательском форке. При конфликте патча или ошибке сборки релиз не создаётся; GitHub Actions сохраняет ошибку в запуске. Такой конфликт должен исправить разработчик.

Приложение проверяет наши релизы через JobScheduler примерно раз в сутки при наличии сети и показывает уведомление. Оно открывает страницу загрузки APK; установку пользователь подтверждает в Android. Точное время фоновой проверки зависит от Android/энергосбережения. Кнопка «Проверить обновления» открывает страницу релизов вручную. Официальный встроенный проверяющий обновления отключён при сборке, чтобы не предлагать APK с другой подписью.

Для расписания копия workflow находится в существующей основной ветке форка (`dev`); его checkout явно берёт `custom/home-wifi` и фиксирует коммит до начала сборки. Основная ветка не меняется. Доработки продукта, патч и сценарии хранятся в `custom/home-wifi`. При изменении самого workflow обновлять его копию и в `dev`.

GitHub Actions secrets:

- `HOME_ANDROID_KEYSTORE_BASE64` — PKCS12 keystore, передавать через stdin, не через чат.
- `HOME_ANDROID_KEYSTORE_PASSWORD` — пароль keystore.
- alias ключа — `amnezia-home`.

Ключ и пароль хранятся локально вне проекта, в закрытом каталоге `~/.config/ai-mcp/secrets/amnezia-home/` (каталог 700, файлы 600). Сохраните защищённую резервную копию: новый ключ не сможет обновлять установленные APK со старой подписью. В репозитории и APK приватного ключа нет.

`versionCode = 1000000 + github.run_number`, локальная первая сборка — 1000000. Не переименовывать workflow и не сбрасывать нумерацию без повышения базы: Android требует возрастающий versionCode. Каждый релиз указывает официальный тег, коммит кастомных исходников и хеш патча.

## Воспроизводимая сборка

`prepare.py` принимает **отдельный чистый checkout** официального тега, `--version-code` и необязательный `--patch`. Он отказывается применять патч при изменённых tracked-файлах или изменении ожидаемого контракта. Не запускать его поверх рабочего дерева с нашей уже применённой правкой.

`build.sh` запускается из подготовленного checkout. Нужны Qt 6.10.3 (desktop и Android arm64, модули как в workflow), CMake/Ninja, Python 3.12/Conan 2.28.0, JDK 17, SDK 36/build-tools 36.0.0, NDK 27.0.11718014 и переменные окружения, перечисленные в скрипте. На macOS отдельно задать `QT_HOST_PATH` на каталог `macos`, на Linux по умолчанию используется `gcc_64`.

Чтобы обновить патч после изменения исходников, сформировать diff только перечисленных Android-файлов и `PageSettingsConnection.qml` относительно 5.1.0.6. Не добавлять изменения submodule, build output, ключи или локальные журналы. Затем проверить применение к чистому checkout и провести ревью.

## Приёмка на телефоне

- Дома: включённая автоматика выключает VPN, обычный интернет работает.
- Уход: отключение домашнего Wi-Fi запускает VPN через мобильную сеть при заблокированном экране; проверить реальный трафик/внешний IP, а не только значок.
- Чужой Wi-Fi: VPN включён. Возврат домой: VPN выключается.
- Роуминг/краткий обрыв: задержка не вызывает лишнего переключения. Два домашних SSID поддерживаются.
- Отзыв разрешений/выключение геолокации: понятный статус, нет ложного распознавания дома. После возврата разрешений автоматика восстанавливается.
- Перезагрузка дома и вне дома, ограничения батареи Vivo, повторный запуск после force-stop.
- Обновление: второй APK подписан тем же сертификатом, имеет больший versionCode и устанавливается поверх первого с сохранением профиля, SSID и настройки включения.

До прохождения этих сценариев функциональность на устройстве не считается принятой. На момент подготовки исходников полный APK и эти проверки ещё не выполнены; unit-проверка политики сети и статические проверки CI не заменяют их.
